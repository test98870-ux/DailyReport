# 데일리 리포트 Android 2.1.2

갤럭시에서 **PC 서버 없이 직접 수집·저장·열람**하는 클리핑 앱입니다. Python 수집 코드를 Chaquopy로 앱 안에 포함하고 모바일 전용 화면을 제공합니다. 기존 PC 서버는 별도로 사용할 수 있습니다.

## 사용 방식

1. 앱을 설치하고 **지금 수집**을 누릅니다. 최초 실행에는 샘플 자료를 자동으로 넣거나 네트워크 수집을 시작하지 않습니다.
2. 하단 **전체 / 뉴스 / 리포트 / 공시 / 보관함**에서 자료를 탐색합니다.
3. 제목·출처 검색, 읽음 상태, 카테고리, 저장된 전체·최근 1/3/7일 필터를 조합합니다.
4. 제목을 누르면 본문 화면이 열리고 읽음으로 표시됩니다. 본문은 16~24px로 조절할 수 있습니다.
5. **보관**으로 다시 읽을 자료를 모읍니다. **원문 보기**는 휴대폰 브라우저에서 기사나 PDF를 엽니다.
6. 설정에서 수집 소스, 수집·정리 기준(한국 시간 1/3/7일 전 16시부터), OpenDART 인증키를 변경합니다.

**AI 호출·AI 요약·모델 다운로드는 없습니다.** OpenDART 키는 공시 조회용이며, 없어도 나머지 소스는 동작합니다. 사이트 HTML과 공식 공시 API를 기존 코드로 파싱합니다. 네이버 리서치의 새 서비스는 공식 화면에서 사용하는 공개 JSON 목록에 대응했습니다.

**백그라운드·예약·주기적 수집은 없습니다.** 수집은 버튼을 눌렀을 때만 시작하고 화면을 떠나면 중단을 요청합니다. 이미 전송한 HTTP 요청은 응답 또는 시간 제한(수집 요청은 최대 20초) 이후 끝날 수 있으나 새 페이지나 다음 소스 수집을 이어가지 않습니다. 외부 브라우저를 여는 경우도 앱 화면을 떠나는 동작에 해당합니다.

## 모바일 레이아웃

- 좁은 화면은 한 열 카드, 600px 이상은 두 열 카드
- 고정 하단 탐색과 분리된 본문 화면, 원문·읽음·보관 하단 동작
- 상태 표시줄·카메라 영역·시스템 탐색·키보드 공간 반영
- 44~48px 이상의 주요 터치 영역, 긴 한글 제목 줄바꿈
- 수집 진행·중지·소스별 성공/빈 목록/미설정/실패 안내
- 긴 목록은 40개씩 추가 표시해 한 번에 만드는 화면 요소 제한
- 화면 회전 시 진행 중인 수집과 현재 화면 유지
- 홈 이동·앱 재실행 시 읽던 기사·스크롤·글자 크기·목록 필터 복원
- 2.1.2에서 Android 내부 저장소에 화면 상태를 즉시 기록하고 사진 영역을 미리 확보해 강제 종료·지연 사진 로딩에도 읽던 위치 유지

검증용 화면 이미지는 `artifacts/mobile-preview/`에 있습니다. 브라우저 미리보기의 기사와 숫자는 테스트 데이터이며 실수집 결과가 아닙니다.

## 설치

저장소 루트의 `artifacts/daily-report-debug.apk`를 휴대폰에 복사해 열면 설치할 수 있습니다. 설치에 사용하는 파일 앱의 출처 허용이 필요할 수 있으며, 회사 관리 정책이나 기기 보안 정책이 적용되어 있다면 해당 정책을 확인하세요.

USB로 설치하려면 휴대폰의 USB 디버깅을 켜고 PC 연결 허용 창을 승인한 뒤 다음을 실행합니다.

```bash
bash scripts/install-android.sh
```

기기가 여러 대면 대상을 지정합니다.

```bash
ANDROID_SERIAL=기기시리얼 bash scripts/install-android.sh
```

수동 명령은 아래와 같습니다.

```bash
adb install -r artifacts/daily-report-debug.apk
adb shell am start -n kr.dailyreport.app/.MainActivity
```

서버 실행, 서버 주소 입력, 포트 개방, USB reverse는 필요하지 않습니다. 설치 후 USB를 분리하고 Wi-Fi나 모바일 데이터로 수집할 수 있습니다.

## 저장과 네트워크

- 자료·읽음·보관·기사 본문 캐시는 앱 내부 SQLite에 저장됩니다. 2.1.0부터 수집 시작 시각 이전에 발행된 자료를 자동 정리합니다. 보관함에 넣은 자료는 유지합니다.
- 처음 열어 본 뉴스 본문을 저장하며, 저장한 본문 텍스트는 오프라인에서 다시 읽을 수 있습니다. 사진과 원문/PDF는 별도 저장하지 않아 인터넷이 필요합니다.
- 앱 내부 저장이므로 PC 데이터·다른 기기와 자동 동기화되지 않습니다. 앱 삭제/데이터 초기화 시 저장 자료가 삭제됩니다. 내보내기·복원 기능은 포함하지 않습니다.
- OpenDART 키는 앱의 비공개 설정 파일에 보관하며 화면이나 수집 오류에 원문 키를 반환하지 않습니다. Android 백업과 기기 전송 대상에서도 앱 데이터를 제외합니다. 루팅된 기기나 디버깅 권한으로부터 보호하는 별도 암호화 저장소는 아닙니다.
- 소스에서 제공하는 목록과 기존 수집 건수 상한을 사용하므로 모든 과거 기사를 가져오는 기능은 아닙니다. 기간 설정은 뉴스에 적용합니다. 모바일의 네이버 리포트는 주말에도 최신 목록을 소스별 건수 상한 안에서 가져오며, 다른 리포트·공시는 기존 소스별 범위를 사용합니다. 수집 후에는 모든 종류의 자료에 동일한 자동 정리 기준을 적용하므로, 주말에 가져온 오래된 리포트도 보관함에 없다면 정리될 수 있습니다.
- 사이트 차단, 접속 지역·이동통신망, HTML 구조 변경, API 제한에 따라 일부 소스가 실패할 수 있습니다. 수집 실패를 이유로 자료를 삭제하지는 않으며, 발행 시각에 따른 자동 정리는 별도로 적용됩니다.
- 국내 리포트·공시의 일부 HTTP 주소 수집을 위해 네트워크 cleartext 허용이 포함됩니다. 기사 본문 WebView에는 원격 페이지를 삽입하지 않으며, 로컬 화면의 HTTPS 정책 때문에 HTTP 사진 일부는 표시되지 않을 수 있습니다.
- 수집 결과의 ‘저장 처리’ 건수는 기존 행의 갱신을 포함합니다. 새로 추가된 고유 항목 수와 다를 수 있습니다.

## 자동 정리와 재등록 방지

- 기본 기준은 **한국 시간 어제 16시**입니다. 수집·정리 기준을 3일/7일로 바꾸면 각각 3일/7일 전 16시가 됩니다. 기준 시각과 같거나 이후인 자료는 남깁니다.
- **발행 시각**을 기준으로 뉴스·리포트·공시를 정리하며, 읽음 여부는 상관없습니다. 보관함에 넣은 자료는 기간과 관계없이 유지합니다. 보관 해제 후에는 다음 정리 시 기준이 적용됩니다.
- 날짜만 제공하는 리포트·공시는 기존 파서처럼 해당 날짜 0시로 판단합니다. 날짜를 해석할 수 없는 항목은 임의 삭제하지 않습니다.
- 앱을 열거나 돌아와 목록을 불러올 때, 수집 전후, 설정 저장 시 로컬에서 정리합니다. 앱을 사용하지 않는 동안 실행하는 서비스·예약 작업은 없습니다.
- 정리 시 목록 행, 읽음 표시, 저장한 본문을 함께 삭제하고 정규화된 URL의 SHA-256 식별 기록만 유지합니다. 기록에는 삭제된 제목·URL 원문·본문을 넣지 않습니다.
- 정리 기록은 만료시키지 않습니다. **기간을 다시 넓혀도 정리한 자료는 재등록되지 않습니다.** 앱 삭제/데이터 초기화 시에는 기록도 사라집니다.
- 사이트 목록 응답에 이미 정리한 자료가 포함될 수는 있지만 앱 DB에 다시 저장하지 않습니다. 네이버·다음 뉴스의 URL 별칭과 네이버 리서치 구/신 주소를 정규화하며, URL 없는 자료는 소스·제목·발행 시각으로 식별합니다.
- 같은 제목이라도 URL이 다른 자료는 별개로 취급합니다. 사이트가 전혀 다른 식별 주소로 재발행한 글을 의미상 같은 기사로 판단하는 AI 기능은 없습니다.
- 보관함 보호, 중복 행 정리, 본문 삭제, 재등록 방지 기록 추가는 트랜잭션으로 처리합니다. 정리 중 오류가 나면 함께 되돌립니다. SQLite의 빈 공간은 새 데이터 저장에 재사용하므로 DB 파일 크기가 즉시 작아지지 않을 수 있습니다.

## 빌드

JDK 17 이상(JDK 21 검증), Python 3.14, Android SDK Platform 36 및 Build Tools 35.0.0, 인터넷이 필요합니다. Android Studio에서 이 폴더를 열거나 `ANDROID_HOME` 또는 `local.properties`의 `sdk.dir`로 SDK 경로를 지정합니다.

```bash
cd android
./gradlew assembleDebug testDebugUnitTest lintDebug
```

빌드 결과:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

저장소 루트에서 복사·서명 확인:

```bash
mkdir -p artifacts
cp android/app/build/outputs/apk/debug/app-debug.apk artifacts/daily-report-debug.apk
sha256sum artifacts/daily-report-debug.apk > artifacts/daily-report-debug.apk.sha256
```

앱 ID는 `kr.dailyreport.app`, 버전 `2.1.2`, min SDK 26 / target SDK 36입니다. ARM64 갤럭시용 `arm64-v8a`와 테스트 에뮬레이터용 `x86_64`를 포함합니다. Python 런타임 때문에 기존 서버 연결형 APK보다 크기가 커집니다. PC의 DB·`.env`·인증키는 APK에 포함하지 않고 공유 Python 소스 5개와 `sources.json`만 복사합니다.

개인 설치용 debug 서명입니다. 이전 1.0 APK와 같은 debug 키라면 업데이트 설치할 수 있습니다. 이 환경의 키는 `~/.android/debug.keystore`입니다. 다른 키로 빌드한 APK는 덮어쓰기 설치가 실패할 수 있으며, 앱을 삭제하면 저장 자료가 사라지므로 키를 유지하세요. Play Store 공개 배포용 release 서명은 포함하지 않습니다.

## 검증 재현

빌드별 실제 확인 결과는 [검증 기록](VALIDATION.md)에 정리했습니다. 이전 에뮬레이터 장애 기록과 연결된 갤럭시 검증 결과를 구분해 기록합니다.

Python 테스트는 실제 DB를 변경하거나 외부 사이트에 접속하지 않습니다.

```bash
python3 -m unittest discover -s tests -v
```

브라우저 UI 검증은 Playwright와 Chrome이 필요합니다. 테스트 데이터가 있는 브리지를 주입해 모바일 5개 크기, 가로 넘침, 목록 더 보기, 검색, 안전한 문자 표시, 읽기·글자 크기·보관·설정·수동 수집 UI를 확인합니다.

```bash
PLAYWRIGHT_MODULE=/설치경로/playwright node tests/mobile-ui.cjs
```

Android 런타임 smoke test는 캐시 디렉터리에 격리된 테스트 DB를 만들고, 내장 Python 시작·SQLite·직접 수집·읽음·보관·본문 캐시·중단을 확인합니다. `-e live true`를 지정하면 네이버 리서치 한 소스를 실제로 조회합니다. 운영 앱의 DB는 사용하지 않습니다.

```bash
cd android
./gradlew assembleDebugAndroidTest
cd ..
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb install -r android/app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -e live true kr.dailyreport.app.test/kr.dailyreport.app.MobileSmokeTest
```

실제 갤럭시에서는 설치·사이트별 수집·모바일 데이터 전환·본문/PDF 열기·글자 확대·화면 회전·홈 이동 중 수집 중단을 추가 확인해야 합니다.

## 구현 참고

[Chaquopy 공식 Gradle 설정](https://chaquo.com/chaquopy/doc/current/android.html)에 따라 Python 3.14와 Android Gradle Plugin 8.13.2를 구성했습니다. Java 브리지는 패키지에 포함된 HTML/CSS/JS에만 연결하며, 외부 스크립트·프레임·네트워크 fetch를 CSP로 차단합니다. 기사 제목과 본문은 HTML 실행 없이 텍스트 노드로 표시합니다.

2.0.1의 읽던 화면 복원 실기기 회귀 테스트는 연결된 기기를 명시하고 실행합니다. 기존 뉴스 한 건을 열고 홈 복귀 및 앱 강제 종료·재실행을 확인합니다. 재수집·데이터 초기화를 실행하지 않습니다. 단, 2.1.0부터 앱 시작/복귀 시 발행 시각에 따른 자동 정리는 정상 적용됩니다.

```bash
ANDROID_SERIAL=기기시리얼 node tests/android-resume.cjs
```
